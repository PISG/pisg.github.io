What it is

A log file in, a statistics page out.

pisg is one Perl script and a config file. It reads the logs your bot or client already writes, counts everything worth counting, and writes a self-contained HTML page you can drop on any web host — including GitHub Pages.

01

Nothing to install

No database, no cron requirement, no web framework, no build step. Perl 5 and a text editor. Run it by hand or from cron as often as you like.

02

Reads the logs you have

eggdrop, ZNC, mIRC, irssi, XChat, AdiIRC, BitchX, energymech, KVIrc, supybot and two dozen more. Gzipped and bzipped logs are read as they are.

03

Statistics people actually read

Not just line counts: who talks to whom, who owns the night shift, whose words are their own, and how much of the channel rests on five people.

New in 1.0a — a relation map, four new themes that follow the reader's light/dark setting, a landing page for several channels, and profiles your users manage from IRC. Read the 1.0a changelog →

Quick start

Four commands and one config file.

This is the whole thing. The example below uses an eggdrop's daily logs; swap Format and LogDir for whatever writes your logs.

setting up pisg
1
git clone https://github.com/PISG/pisg.git
Or grab a release tarball from the releases page and unpack it. Nothing is compiled and nothing is installed system-wide — the folder you unpack is the program.
2
cp pisg.cfg.example pisg.cfg
The example config lists every option with a one-line explanation, so you can read it instead of the manual. Then edit the channel block: 
<set ColorScheme="modern">
<set HomeLink="index.html">

<channel="#nightshift">
 Format     = "eggdrop"
 LogDir     = "/home/eggdrop/logs/nightshift/"
 Network    = "Undernet"
 Maintainer = "vox"
 OutputFile = "site/nightshift.html"
</channel>
3
./pisg
On Windows: perl pisg. Every channel in the config is parsed in one run; a channel that cannot be read is skipped with a warning and the others still get their page. Add -ch, -l and -o to do a single channel straight from the command line — ./pisg --help lists the lot.
4
rsync -a site/ you@host:/var/www/stats/
Upload the folder. The pages are self-contained HTML — the CSS and the bar images are inside the file — so there is nothing else to copy and nothing to configure on the server. Put site/index.html next to them for the landing page.
Want it updated by itself? Add one crontab line — see scripts/crontab in the distribution, or Running pisg in the manual.

New in 1.0a

Same parsers, same config — a much better page.

Everything 0.80-preview2 did, pisg 1.0a still does: the same log formats, the same statistics, the same pisg.cfg. Nothing you have set up has to change.

▣

Who talks to whom

An interactive map of the channel's conversations: who addresses, mentions and answers whom. Click a nick or a line for the detail. Bots are left out.

▤

Four new themes

modern, midnight, amoled and terminal, all generated from one stylesheet. The eight classic schemes are untouched — and a theme of your own is one CSS file, or two minutes in the creator.

☰

Section navigation

A menu down the left on wide screens, a slim bar on phones, and a marker on the section you are reading. It works with JavaScript switched off.

⌂

A landing page

The statistics of your statistics: every channel compared, a 24-hour profile each, the last 30 days, and a button into each page. One static file, no PHP.

◉

Seven new sections

Channel overview, closest pairs, social roles, time personalities, who carries the channel, and the word each person uses that nobody else does.

⚙

Profiles from IRC

An optional eggdrop script lets people set their own picture, link and merged nicks with !pisginfo — authenticated against their network account.

↻

Several channels, one run

One config, any number of channels. A channel that cannot be read no longer stops the others, and pisg exits with a real error status when something fails.

⚖

Safer output

A page is written to a temporary file and moved into place only when it is complete, so a failure can never replace a good page with half of one.

☐

Phones included

Readable from 360 px up, with a viewport tag, full UTF-8 handling, and wide tables that scroll inside their own section instead of dragging the page sideways.

Optional tools

For the people who run the channel.

None of these are required to use pisg. They live in scripts/ and solve the things that otherwise mean editing config files by hand.

eggdrop-pisg.tcl tcl 8.6 Lets people manage their own profile from the channel: !pisginfo for sex, picture and link, !pisgmerge to count their other nicks as one person, !pisgstats for the page address. Identified by network account, rate limited, and it can never overwrite a <user> line you wrote yourself. 107 tests ship with it. Docs →
pisg-autoalias.py python 3 Nicks seen on the same authenticated host are the same person. Writes an include file for pisg and can run before every pisg run. Your own <user> lines always win; shared hosts, gateways and bouncers are never merged. Docs →
adiirc2eggdrop.py python 3 Turns an AdiIRC (or similar) client log into eggdrop or ZNC logs, so years of history you kept by accident can join the statistics. Public events only, local time converted to UTC, never overwrites a file, and it stops where your real logging starts. Docs →
znc-setup.sh shell Puts converted logs into a ZNC account's log folder and gives pisg — running as a different Unix user — read access to exactly the channel folders it needs. It prints what it would do before it changes anything. Docs →

FAQ

Questions people actually ask.

I have no bot. Can I still make stats?

Yes, if your client keeps logs with timestamps. mIRC, AdiIRC, irssi, XChat, KVIrc and others are all supported formats — turn timestamped logging on, point Logfile at the file and run pisg. A bot or a bouncer is only better because it is online when you are not.

Do I need a web server?

No. The page is a single HTML file with the stylesheet and the bar graphics inside it, so opening it from your disk works. To share it, any static host will do — GitHub Pages, a shared account, the public_html folder you have had since 1999. The landing page is static too: no PHP and no cron job.

Will 1.0a break my existing setup?

It is an alpha, so keep the version you run now until you have tried this one on a copy. That said: your pisg.cfg keeps working as it is, and every old colour scheme looks as it did. Two things to know: the new sections are on by default (set ShowOverview, ShowRelations, ShowTimePersonalities, ShowConcentration, ShowSignatureWords and ShowNavBar to 0 for the old page exactly), and pisg now exits with status 1 when it fails instead of pretending everything went fine. Check any script that read its exit code.

How long does a run take?

Minutes for years of logs, seconds once the cache is warm. Set CacheDir and pisg keeps the parsed result of each log file, so a nightly run only reads what changed. The example on this site — 617,000 lines across three channels — takes about forty seconds from cold.

Can I keep people out of the statistics?

<user nick="somebot" ignore="y"> leaves a nick out entirely, and sex="b" marks it as a bot so the relation map skips it. BadUrls keeps image hosts and spam out of the URL list, and IgnoreWords does the same for words. If someone asks to be left out, that one line is the whole answer.

Is anything sent anywhere?

No. pisg reads local files and writes local files. It opens no network connection and has no option that would make it open one.

Where do I get help?

The channel: #pisg on Undernet (irc.undernet.org). For bugs and patches, the issue tracker on GitHub. The old SourceForge trackers and mailing list are read-only history now.
